# 默认 Agent 配置验收

日期：2026-09-06。

## 配置与迁移

新项目启用研报Agent、数据Agent、写作Agent，全部为普通可编辑、可删除的项目 Subagent，模型跟随主模型。数据角色启用当前全部 **5** 项 AKShare Skills（原计划“六项”为计数错误）。主 Agent 的配置和聊天委派限制不变。

已有项目只在没有初始化版本标记时补充；按去除空白的名称匹配，保留同名角色的一切设置。达到 12 个上限时记录未添加角色。删除、改名、禁用或清空列表后不会自动重新补充。管理页更多菜单可主动补充默认角色。

搜索开启但缺少 TAVILY_API_KEY 时返回明确配置提示。AKTools、模型、文档组件仍依赖本机已有服务，不自动配置密钥或授予 MCP。

## 自动化

174 项测试通过；类型检查、lint、生产构建与 `git diff --check` 通过。

覆盖默认角色权限、深拷贝、同名禁用角色保留、主权限不变、一次性迁移、删除后不复活、容量限制和手动补充幂等。实际工具装配测试确认只有数据角色拥有 Bash、Skill 脚本和数据库修改；只有写作角色拥有文档生成。服务端空配置不会隐式生成默认角色。

## 浏览器

在现有本机项目页面完成：显示三个预置角色；禁用数据角色并删除写作角色，刷新后仍保持；更多菜单手动补充写作角色，不改变数据角色禁用状态；修改写作角色名称并刷新，修改保留。验收结束已恢复三个角色的默认名称和启用状态。

新项目工厂和跨项目配置独立性通过自动化覆盖；本轮没有通过系统目录选择器新绑定项目。浏览器已确认 Workflow 设置保留“使用全部已启用 Subagent”；未逐项执行聊天选择范围操作。

## 真实模型与工具

隔离临时项目，使用已配置 DeepSeek V4 Pro，完成数据 → 研报 → 写作三节点工作流：4 次实际文件读取、1 次实际 Word 生成、7 条 Trace。脚本为 `scripts/default-agents-smoke.mjs --live`，机器结果保存在 `.local-data/default-agents-smoke-latest.json`。临时项目、数据库及文档随验收清理，不向用户项目写入测试业务数据。

这验证了角色权限和工具链路，不代表研究内容质量全部通过：模型最终总结将样本 A 的 120−80 错写为 30，尽管总额写为 70。该语义错误已记录；没有把本次验收当成财务准确性验证。外部联网搜索和 AKShare 实际财经接口本轮未进行真实请求；AKTools OpenAPI 可达不等于全部上游数据源可用。

## 本机服务

验收开始时网页可用而 Runtime 不可达。已重新启动 Runtime 与网页，并单独启动 AKTools。本机 AKTools 的 `/version` 探测未在启动等待期限内返回，使用独立 AKTools 进程提供服务；`/openapi.json` 返回 200。未改动启动脚本，也未宣称该启动探测问题已修复。
