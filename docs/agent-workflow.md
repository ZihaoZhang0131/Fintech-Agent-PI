# Agent Workflow

Workflow 与聊天并列，仍通过 `npm run dev` 或 `npm start` 启动完整本机服务。顶部切换到 Workflow 后，复用项目侧栏，以对话方式输入任务。默认使用项目已启用的 Subagent；没有可用角色时，从 Subagent 管理页面添加，不会自动授予工具权限。

## 对话界面

每个 WorkflowConversation 关联同项目多轮运行。任务完成、失败或停止后，输入框继续可用；追问创建新的运行，携带最近 12 条用户／回答消息（单条最多 4,000 字符）和历史运行引用。Plan Agent 可以按需读取上一轮完整结果；不重放旧工具调用。活动运行期间发送内容复用 feedback。

用户输入、规划说明、补充问题和最终回答持久化为稳定消息 ID，和状态事件同事务保存。旧运行保持原 ID 映射成单轮对话；能恢复的历史内容才显示，不补造缺失时间。

- 规划消息内显示紧凑 DAG，节点状态原位更新。上一轮规划自动折叠。
- 大图、计划版本和编辑在展开视图；结果、原始输入、尝试及 Trace 在临时节点抽屉。
- 运行中空输入显示停止；填写补充要求时显示发送及小型停止；暂停／等待／中断时空输入显示继续。
- 命令审批出现在执行消息中。连接问题在输入框附近提示。
- 草稿按对话保存，切换模式、管理页面或刷新可恢复。阅读历史时不强制跟随进度。
- 资产与设置通过顶部更多菜单进入独立页面。设置只影响下一轮；已有运行限制在运行详情中调整。

前端分为对话容器、消息流、共享 ComposerSurface、资产页、设置页、节点详情和大图／模板操作视图。应用模式与管理页面分别保存状态。

## 执行与恢复

Plan Agent 只拥有工作流工具。提交计划、继续执行、请求输入、结束总结会终止当前 PI 工具轮；本机执行器执行就绪节点后，再开启下一轮规划。每个节点具有独立上下文、结构化完成标准及结果。节点可以使用自身 ReAct 循环核验事实，工作流也可以根据观察调整 DAG。

- 暂停：停止派发，允许正在执行的节点结束；继续时保留有效结果。
- 停止：取消模型及支持取消的工具，禁止新调用，保留已产生的副作用与不确定状态。
- 修改：等待当前节点结束后应用新版本；改变节点及其传递下游失效，无关结果继续有效。
- 重启：未结束运行标记为已中断，用户继续后带着历史结果与操作记录恢复。
- 恢复：先核验是否已经完成，部分完成则补齐。无法核验且无安全补救手段才请求用户输入。不会机械重放未知写操作。

默认同项目一个活动运行、两个并发节点；12 个节点、5 次自动结构修订、每节点 3 次尝试、5 分钟主动执行时间。审批等待不计入时间。暂停后可在运行详情中调整限制。只读工具可并行；所有 Workflow 的潜在写操作共享保守锁。该锁不改变已有聊天或外部程序的并发行为。

## 资产

全局模板保存不可变版本，运行保存独立计划版本。模板运行默认自适应，也可固定节点结构。参数使用 `{{参数名}}`；保存对话框接受“参数名 → 当前值”，将节点任务与完成标准中的当前值替换为占位符。

跨项目使用时明确映射目标 Subagent；目标角色需要具有模板要求的工具、Skills 和 MCP。模板不会自动启用能力或携带密钥。归档不会删除版本和历史运行。再次保存到已有资产会新增版本，不覆盖旧版本。

## 存储和边界

- `.local-data/workflows.sqlite`：对话、消息及运行关联、运行快照、独立尝试与完整结果、操作记录、递增事件、请求去重、模板版本。
- `.local-data/workflow-sql-ledger.sqlite`：SQL 操作回执。与业务 SQLite 通过附加数据库事务共同提交；内部表不出现在业务表列表中。
- `.local-data/traces.sqlite`：每轮规划及节点尝试的 PI Trace；清理 Trace 不影响 Workflow 恢复。

文件操作记录目标、内容校验信息、结果和时间；不提供跨外部系统的事务回滚。SQL 同一操作 ID 只提交一次，新的 Agent 工具决策产生新 ID，仍需要业务键与状态核验。任意 Bash、MCP 调用不承诺恰好执行一次。

启动时将浏览器项目配置校验并保存为运行快照，模型只保存引用，密钥运行时在服务端解析。原聊天 localStorage 和聊天协议保持兼容。新运行使用当前配置，已有运行保持启动时的授权快照。

## 接口

接口均经 `/api/local/workflows` 代理到鉴权的本机 Runtime。

| 接口 | 行为 |
| --- | --- |
| `GET/POST /conversations` | 按项目查询／创建对话 |
| `GET /conversations/:id` | 对话消息与各轮运行快照 |
| `POST /conversations/:id/messages` | 活动运行补充反馈，结束后创建新一轮 |
| `GET/POST /runs` | 按项目列出运行／创建后台运行 |
| `GET /runs/:id` | 运行与计划快照，不载入完整节点正文 |
| `POST /runs/:id/actions` | `pause`、`resume`、`stop`、`feedback`、`edit`、`limits` |
| `GET /runs/:id/attempts/:attemptId` | 完整节点输入、结果、操作与审批关联 |
| `GET /runs/:id/events?after=seq` | 持久化事件 SSE，支持 `Last-Event-ID` |
| `GET/POST /templates` | 资产查询、保存版本、复制、归档 |

所有 POST 携带 `requestId`；重复请求复用结果，不同内容复用 ID 返回 409。运行控制还需 `expectedVersion`，防止覆盖较新的计划。创建、控制和模板操作的回执与状态在 SQLite 事务内提交。SSE 连接关闭不会取消运行。

## 验证

`npm test` 包含 DAG 调度、暂停停止、恢复、写锁、事务去重、跨项目模板映射和断线事件恢复测试。

`node scripts/workflow-smoke.mjs --live` 显式调用已配置模型，在临时项目中执行两个真实文件读取节点及汇合节点，验证 Trace、创建去重、保存模板，然后清理临时项目和凭据副本。验证摘要保存在 `.local-data/workflow-smoke-latest.json`，不包含密钥。

`node --experimental-strip-types scripts/workflow-ui-fixture.mjs` 启动隔离的浏览器验收环境（3001端口），提供模拟长回答及真实无害 Bash 审批，不调用模型或读取生产数据；退出时清理临时数据。
